# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Running the app

```
npx serve -p 5500 .
```

Open `http://localhost:5500/` in a browser. There is no build step — reload the browser after edits.

Campaign data is fetched at runtime from `data/*.json` (see below), so the app must be served over HTTP — opening `index.html` directly via `file://` will fail to load data due to browser fetch/CORS restrictions.

## Validating data (the project's "test")

```
node tools/validate-data.js
```

Runs the same model the page uses (`js/chronicle-model.js`) over `data/*.json`: JSON syntax, duplicate ids, every cross-reference, coordinates, route waypoints/shared legs, asset paths, and `data/i18n/*.json` (unknown ids, positional array lengths, coverage). The rules that need no file system are `ChronicleModel.validateData(raw, { translations })`, shared with the Taller del Cronista (browser); the tool adds the file-system checks (assets, `sw.js` precache). Exit code 1 on errors. Run it after any data or model change. `--data <folder>` checks an exported package before copying it in (its files take precedence over the repo's).

```
node tools/apply-draft.js <cambios.json | package.zip> [--check] [--force] [--data <folder>]
```

Incorporates a draft exported from the Taller into `data/*.json`: only the draft's changes, applied to the current files in each file's own layout; stops (exit 2) when a record changed here after the DM started editing it, unless `--force`; skips changes the data already holds (a second run is harmless); refuses drafts with validation errors. Then run `npm test`.

## Tests

```
npm test              # validator + node --test tests/*.test.js (no dependencies)
npm run test:browser  # tests/browser/smoke.mjs then taller.mjs — playwright-core driving the installed Edge
npm run test:taller   # tests/browser/taller.mjs only (TALLER_ONLY=<regex> for a subset)
```

session numbers never matching stray digits, titles, what was recorded, explicit links only — places with the places they lie in, never links of links —, both languages/accents/case, the reason each entry appeared, the excerpt, the order kept, status AND words, the `index.html` wiring and the tour giving the searches back), the recap (`recap.test.js`), optional event narrative fields (`narrative.test.js`), favourites/history (`library.test.js`), the help centre/glossary/first-visit welcome/contextual hints (`guide.test.js`), the Taller's data core (`editor.test.js`: pointer → map percent at any zoom/pan, suggestions, drafts and bilingual pairs, apply/export byte-identical layouts, conflicts and incorporated exports, validation codes, ids, ZIP, draft files/imports, storage revisions, the whole path through `tools/validate-data.js --data` and `tools/apply-draft.js`), the Taller's wiring (`taller.test.js`: lazy strings complete in both languages, routes never opening the public pane/history/favourites, lazy loading, isolation — IndexedDB only, no HTML from data, no external host —, preview on the draft's model, the map editor's `[data-world]` box), the guided tours (`tour.test.js`: the eight main steps and *Paso N de M*, steps adapting to the campaign's content with fallbacks — never skipped —, help last (`?` / More → Help), the action that moves each step, screens/panels per step, texts and controls in both languages, versioned onboarding keys, the runtime against a stand-in Driver.js and DOM, `index.html` wiring) and the PWA files (`pwa.test.js`). Tests read sources with `readText` (`tests/helpers.js`), which turns CRLF into LF: this checkout uses `core.autocrlf=true`, so files are CRLF on disk and line-based patterns would otherwise miss. The browser suite needs `npm install` once and must run from PowerShell/cmd on Windows — under Git Bash Playwright's `--remote-debugging-pipe` fails and Edge exits immediately. It writes screenshots to `test-results/` (git-ignored). Its offline check starts its own server and stops it to simulate no connection. `tests/browser/taller.mjs` drives the Taller and the map editor on test data in a throw-away profile (never `data/`): coordinates at several zooms/pans, drag, keys, clamping, cancel/confirm, the public map untouched, phone taps, the full create → save → reload → export → validate → apply → re-import path, invalid data, conflicts, an incorporated export leaving the draft, two tabs, a11y basics. ## Architecture

A single **Design Component** (`index.html`, a `.dc.html`-style template) powered by the `dc-runtime` (`support.js`, which loads React 18 from unpkg before booting), plus a plain data-layer script:

- `js/chronicle-model.js` — loaded by a normal `<script>` before `support.js`; exposes `window.ChronicleModel` (and `module.exports` for Node). Pure data: `build(raw, { locale, t, translations, searchTs })` normalizes the JSON files (including legacy records), overlays the content translation for `locale` (English fallback per field; positional arrays only when lengths match) and builds the linked model (`events`, `sessions`, `quests`, `people`, `places` + `…ById` maps, reverse indexes, `routeById`, `issues`); `filterEvents`, `FILTER_PREDICATES`, `matchesCharacters`, `toggleVisibleCharacter`, `selectedCharacterIds`, `search`, `fold` (accent-insensitive), `checkTranslations`, `normalizeLore` (attaches `person.lore`/`place.lore` from `data/lore.json`, read-only), `validateData` (the validator's file-system-free rules, shared with the Taller), places' own map position (`place.ref` = `{xp, yp, precision}` from optional `xp`/`yp`/`mapPrecision`, `MAP_PRECISION`; `place.mapPoint` = the ref, else the first located event's point — what the place page and *View on map* use), `safeExternalUrl` (https-only gate for every external link), presentation order (`chronicleGroups` — groups reversed for latest first, entries inside a group always in recorded order —, `sessionListItems`, `normalizePrefs`/`sortOrders`, `DEFAULT_ORDER` = Chronicle `desc`, Sessions `asc`), the universal search (`searchAll` — groups by kind, one relevance scale 0–5 over `nameKeys` / `searchText` / `contextText`, number queries = session or day, ties by English names; `search` = the Chronicle's quick chips on top of it; `chronicleFilterFor`; `highlightRanges`), the Sessions and Quests searches (`findSessions` / `findQuests` → `{query, searching, number, hits: Map(key → {field, ref, text})}` — a filter, never a ranking: every word in the entry's `find` parts, built in `build()` from what it records and what is explicitly linked to it — a session: title, opening/closing lines, recap, its events' text and kind, its plots, effects, in-world dates, its quests, people and places; a quest: title, summary, objectives, giver, the plots carrying it by `questId`, its events, people and places; places count with their recorded ancestors —, each part with this language's `text` and every language's folded `keys`; a number = that session only / the quests of that session; `findPeople` = the Characters list: the same matches as `person.searchText` (parts `name`/`alias`/`race`/`role`, a catch-all alias part for translated aliases that do not line up), numbers read as words; `hit` = the part that says why, one holding the words in the language on screen first; `excerpt(text, query)` = the reason line around the longest word, cut between words, with ranges to mark), `resolveRef(model, kind, id)`, the Places index (`placeIndex(model,{cmp})` → `groups` [`atlas` | `planes`: top-level places split by `isPlanar`, i.e. the recorded kind `plane`] + story-ordered `childIds` + `branchIds`; `placeOrder` = depth-first ids; `placeTreeView(model, index, {open, query})` = the nested nodes to show — `open` overrides the default (top level open, below closed, `isPlaceOpen`), a `query` shows the universal search's place matches plus their ancestors as context and never touches `open`; `revealPlace` opens only a place's ancestors; places carry `kindKey` = a `PLACE_KINDS` key or `"place"`; `parentId` loops are reported and cut at their first place), the recap (`latestSession` = highest session number with a log; `recapOf` — recorded data only, highlights only from `sessions.json` `recap.highlights`), `guideExamples` (real examples for the tours and the search's suggestions), vocabularies (`EVENT_TYPES` with each type's colour `family` → `ev.typeFamily`, `QUEST_STATUS`, `PERSON_CATEGORIES`, `PLACE_KINDS`, `LORE_FACTS`). No DOM. Relationship logic belongs here, not in `index.html`.
- `js/chronicle-editor.js` — `window.ChronicleEditor` (and `module.exports`): the **Taller del Cronista's data core**, no DOM. Map coordinates (`clientToPercent(clientX, clientY, rect)` through the on-screen box of `[data-world]` — zoom/pan/CSS-proof —, `percentToClient`, `viewToPercent` (MapViewport's arithmetic), `pixelStep`, `nudge`, `coordsText`, `parseCoords`; two decimals stored); `suggestPosition(model, {locationId, excludeEventId})` (the place's `ref` → most-used point of its events → of places inside → nearest ancestor; `source`/`precision` always given; planes never); drafts = record-level changes `{op, en, es, base}` per kind (`session`, `event`, `quest`, `place`, `character`, `npc`; `en` = the object in `data/*.json`, `es` = the `data/i18n/es-AR.json` entry) with `putRecord` (tidy: empty fields dropped unless published empty, published key order kept, new keys at their `FIELDS` place), `deleteRecord`, `revertRecord`, `renameNew`/`renameSession` (new records only, links follow), bilingual pair helpers (`withText`, `withList` keep positional translations aligned), `applyDraft` (untouched records exactly as published; new events after their session; `finishPair`: Spanish-only texts also English, trimmed, empty list items dropped in both languages, `date`/`dateLabel` conventions for new records), `conflicts`/`resolveConflict` (field diff; combine/mine/published), `publishedChanges`/`dropPublished` (changes the published data already holds — an incorporated export — are never conflicts; the Taller drops them, after a backup, when it opens and when it re-reads the published data), `validate` (form checks with codes `taller.v.<code>` per record/field + `Model.validateData` issues the draft introduced), `serialize`/`exportFiles` (each file's own layout: pretty / compact / rows — every data file round-trips byte for byte), `zip`/`unzip` (stored entries, CRC), `parseDraft` (sanitized, malformed entries skipped), `mergeDrafts`, `changesFromFile` (never deletions), `createStore` (IndexedDB `chronicle-taller`: `draft`/`backups` stores, saves checked against `{id, rev}`; memory fallback).
- `js/chronicle-taller.js` + `locales/taller.<code>.js` — `window.ChronicleTaller.create(app, deps)`: the Taller's UI and the map editor's panel/layer, React elements through `h()`; **loaded on demand** by `Component._taller()` (`TALLER_SCRIPTS`), never by a `<script>` tag, never precached (network-first stores them on first use). Its strings live in `locales/taller.<code>.js`, merged by `ChronicleI18n.extend`; only `taller.title/loading/loadError/helpLine` and `mx.title/exit/pickMarker` (used by `index.html`) stay in the main locales, with the same words. It owns its state (draft, save status, forms, the map editor's pending moves) and re-renders through `tlRev`; every change goes through `commit()` (draft in memory at once, IndexedDB after 400 ms; previews and checks follow the *settled* draft 300 ms after typing pauses); previews call the public `_eventVm`/`_sessionVm`/`_questVm`/`_personVm`/`_placeVm` with `app.model` swapped for the draft's model (restored in `finally`), their links made inert. Exports re-fetch the published data (`cache: "no-store"`) before writing.
- `tools/apply-draft.js` — the safe way to publish an exported draft (see above).
- `js/chronicle-tour.js` + `vendor/driver.js/` — `window.ChronicleTour`: the guided tours on the real interface, driving [Driver.js](https://driverjs.com/) 1.8.0 (MIT, vendored unchanged — IIFE `window.driver.js.driver` + `driver.css`, loaded before `support.js`; never edit it, replace it with a newer npm `dist/` copy and re-read its API). `STEPS` are data — `screen` (`ok`/`go` hash), `ui` (more/search/mapPanel/mapPopup), `target` (only elements really on screen; `env.inView` prefers what is already visible, so the page does not scroll), `text` (`tour.<step>T/D`; a function picks a variant by context/element, all listed in `variants`), `done` (the action that moves it on), `perform` (what Next does), `fallback` (when the screen cannot be reached or the element never comes — no step is ever skipped in silence), `none` (the element cannot come: fallback at once), `when` (content-dependent steps, decided before the tour so *Paso N de M* is true) — and `TOURS` lists them: `main` = sections, chronicle, sessions, quests, map, mapCard, find, help (8; help last: `?` or More → Help on phones), `map` and `search` (the map tour shares the marker/card logic). Progress counts every step. `createRunner({driver, app})` closes the spotlight (`park()`, a highlight with no element) before changing screen, establishes each step's screen, waits for the element to exist and stop moving (rAF, no fixed delays; a timeout only ends a wait for an element that never comes), calls `highlight()`; *Siguiente*/*Anterior* act only once the popover rendered (`run.ready`); refreshes only after Driver.js finished moving (`run.settled`), also on resize/fonts/`ResizeObserver`; `clamp()` keeps the popover on screen and off its element (larger free band, shortened text, or beside it on low screens); `sync()` (called from `componentDidUpdate`) advances on `done`, re-highlights re-rendered elements; it restores the `aria-*` attributes Driver.js strips. The popover: *Paso N de M* + bar, *Omitir tutorial* (Driver.js's close button) top-right, *Anterior* · *Siguiente*/*Finalizar*, *Ver más tutoriales* on final steps. `createProgress(storage)` = versioned onboarding flags (`chronicle-tour-version`, `chronicle-tour-completed`, `chronicle-tour-invite`; `VERSION` 3; bump it to offer the tours again; removes the old `chronicle-tutorial-seen`).
- `js/chronicle-library.js` — `window.ChronicleLibrary.createLibrary(storage)`: favourites (newest first) and recently viewed (20 kept, 5 shown, no consecutive duplicates) as `{kind,id}` references in `localStorage` (`chronicle-favorites`, `chronicle-recent`, stored as `{v:1,items}`); corrupt data reads as empty, blocked/full storage falls back to memory (`persistent` false), `prune(exists)` drops references to entries that no longer exist (the page never prunes against an offline copy).
- `sw.js` + `manifest.webmanifest` — PWA. Network first for navigations, scripts and `data/*.json` (revalidated with `cache:"no-cache"`, 6 s timeout → saved copy marked `x-chronicle-offline: 1`, which the page reads to show its offline note); stale-while-revalidate for `assets/`; cache-first for unpkg/Google Fonts. `assets/exandria-map.jpeg` is never intercepted or stored. Caches `chronicle-shell-<VERSION>` / `chronicle-runtime-<VERSION>`; bump `VERSION` when `PRECACHE` changes (the validator and `pwa.test.js` check every listed file exists and every startup file is listed). Icons are rendered from `assets/app-icon.svg` by `tools/make-icons.mjs`.
- `js/chronicle-map.js` — `window.ChronicleMap`: pure map geometry. `routeLayers(model, ids)` (individual polylines + shared legs drawn once), `groupSpots` (one spot per exact coordinate), `clusterSpots` (agglomerative, zoom-dependent, markers never overlap), `separationScale`, `clampShift`.
- `js/i18n.js` + `locales/en.js`, `locales/es-AR.js` — `window.ChronicleI18n`: `createTranslator(code)` → `t(key, params)` with `{param}` interpolation, `{one,other}` plurals, English fallback; `t.dict` is the merged nested dictionary passed to the template as `t`. Locale files are scripts (not JSON) so the first paint is already translated. Default `es-AR`, preference in `localStorage` `chronicle-lang`.
- `index.html` — template + CSS (in `<helmet>`) + the `Component` logic: routing, view-model builders, map viewport. **No visible text is hard-coded**: template strings are `{{ t.section.key }}`, JS strings `this.t("section.key", params)`; add every new key to both locale files.

### dc-runtime concepts

- **`<x-dc>`** — wraps the entire template; the runtime strips it and mounts a React root in its place.
- **`{{ expr }}`** — template interpolation; `expr` resolves against the values returned by `renderVals()`. Keep expressions to plain paths.
- **`<sc-for list="{{ … }}" as="item">`** / **`<sc-if value="{{ … }}">`** — structural directives compiled into React elements.
- **`<helmet>`** — injects `<link>`, `<style>`, `<script>` tags into `<head>` at runtime.
- **`<script type="text/x-dc" data-dc-script>`** — the logic block; must define `class Component extends DCLogic`. The `data-props` attribute carries JSON metadata for the editor.
- **`style-hover="…"`** — pseudo-class helper that injects a scoped CSS rule via the pseudo sheet.
- **`DCLogic` / `StreamableLogic`** — base class. Key methods: `renderVals()`, `setState(update, cb)` (state is applied synchronously; `cb` runs after commit), `componentDidMount()`, `componentDidUpdate()`, `componentWillUnmount()`.
- Returning the *same* React element object from `renderVals` lets React skip that subtree — the map's route SVG, pins and the detail pane are memoized (`this._memo`) so panning/zooming doesn't rebuild them.

**Runtime gotchas (learned the hard way):**
- The browser parses the `<x-dc>` markup as real (hidden) DOM before the runtime runs. Template `<img>` tags therefore download unless they have `loading="lazy"`, and inline-handler attributes that fire on their own (`onLoad`) throw. Load images from JS (`new Image()`) when you need a load callback.
- `{{ }}` text interpolation wraps strings in a `<span>`, so `<option>` lists are built in JS as React elements (see `options()`), and rendered as `{{ c.opt.quest }}` inside `<select>`.
- Base element rules must use `:where(.cc-app) button` style selectors; a plain `.cc-app button` outranks component classes like `.cc-btn`.
- `class` → `className`; camelCase attributes (`onClick`, `tabIndex`, `autoComplete`, `enterKeyHint`) are passed through as React props.
- That camelCase encoding (`support.js` `CAMEL_ATTR_RE`, ` word=` with a capital) runs over the whole `<x-dc>` markup, the `<helmet>` stylesheet included: an SVG data URI in the CSS must not use `viewBox=` & co. (use `width`/`height`). `design.test.js` checks the stylesheet for it.

### index.html structure

Six sections (plus the hidden `saved` section: favourites + history, reached from the top-bar star / More, never a tab; and the hidden `taller` section: the Taller del Cronista, `#/taller`, `#/taller/tab/<tab>`, `#/taller/<kind>/<id>` — `TALLER_KINDS` —, reached from the help's last line), switched by hash routes `#/<section>[/<kind>/<id>]` (works on GitHub Pages):

| Section | Content |
|---------|---------|
| `chronicle` (home) | Narrative timeline grouped by campaign day or session, sticky search + combinable filters, cross-entity quick results |
| `sessions` | Session list with gaps for unrecorded sessions; its own search above the order (results in the chosen order, no gaps) |
| `quests` | Quests by status; its own search above the status filter (status AND words) |
| `characters` | Party + NPCs/deities/creatures/factions; its own search (name, alias, kind, role) with a count and the reason on a row's quiet line |
| `places` | The atlas index: nested disclosure lists (Atlas of Exandria / Other planes), a contextual filter, Expand all / Collapse all |
| `map` | The original pannable/zoomable map: pins grouped per coordinate (click cycles), counter-scaled `Session N` captions, dashed route, popup, party toggles |

Detail kinds (`event`, `session`, `quest`, `character`, `place`, and `recap` = "Previously on…" for a session number, linked from the Chronicle and Sessions headings for the latest session) open the reading pane (`.cc-detail`): beside the list at ≥1024px, full-screen below. The section stays in the URL, so links inside a detail keep you in the current section (e.g. `#/map/session/8` = map + session log beside it, like the original right panel). `#/map/at/<eventId>` focuses/selects a pin without opening the pane (used on phones); `#/map/near/<placeId>` centres a place's own position (phones; `placeMapHref`); `#/map/edit[/<eventId>]` and `#/map/editplace/<placeId>` are the map editor (`MAP_KINDS`, `isMapEdit`). `isEntryRoute(r)` (a public entry: never a Taller route) decides the reading pane, focus, recently viewed and the favourite star. Below 720px the top tabs become a bottom nav (Chronicle, Sessions, Quests, More).

Key pieces of `Component`:
- Routing: `parseHash`, `navigate(hash,{replace})`, `_routeChanged` (keeps `_stack` to know whether in-app Back can use `history.back()`), `_afterRoute` (restores per-section list scroll and per-route detail scroll, keeps the open card visible, syncs the map).
- View-model builders: `_buildChronicle`, `_buildSessions`, `_buildQuests`, `_buildPeople`, `_buildPlaces`, `_buildDetail` → `_eventVm` / `_sessionVm` / `_questVm` / `_personVm` / `_placeVm`, `_loreVm` (the one "Lore of Exandria" block shared by character and place pages, `d.lore` → `lo`), `_buildMap` (+ `_buildPins`, `_buildRoutesSvg`). `renderVals()` only builds the visible section.
- `MapViewport` — wheel/drag/pinch, clamping, centering; attached through the `vpRef` callback ref because the map only mounts on the `map` route. Touches/wheel starting inside `[data-nopan]` (popups, panel) are ignored so lists can scroll. `_centerSoon` retries centering until layout settles unless the user interacted; `_coverScale` keeps the map filling tall phone screens.
- Map editor: in `_buildMap`, `isMapEdit(r)` swaps the pins for the Taller's (`tl.mapEvents()`: the draft's located events minus the one being placed), every marker choosing what to place (`_buildPins(..., pick)`), no popups; `mp.editLayer` (the marker being placed, its previous position and a suggestion ring, drawn by the Taller in the world's own % coordinates), `onVpPointerDown`/`onVpClick` (a tap/click places; a pan > 6 px does not), `mp.editSheet` (<1024px) or `mx.aside` (the reading pane, ≥1024px). The world div carries `data-world` (the box the pointer is converted through); `MapViewport` ignores touches starting on `[data-nodrag]` (the marker) but still zooms with the wheel there.
- Map: `_mapEvents` (shared filters, memoized) → `_markers` (`ChronicleMap` clusters at a quantized zoom) → `_buildPins`; `_buildRoutesSvg` draws `routeLayers` for `selectedCharacterIds(filters.pcs)` only — narrative filters never touch routes. A marker with several events opens a list popup (`state.mapList` = event ids); `_popupFrame` keeps popups on screen and is corrected once with the measured height (`data-popup` + `componentDidUpdate`).
- Places index: `_buildPlaces` (memoized on the model, `state.placesOpen`, `state.placesQuery`, the open place and `isWide`) → `_buildPlacesNow` builds the tree with `h()` as nested `<ul role="list">` (a recursive list cannot be an `sc-for`): per place a `.cc-node-row[data-place]` with the caret (`button.cc-twisty`, `aria-expanded`, `aria-controls` → its `ul.cc-tree-sub`, kept in the DOM, hidden and empty, while folded), the link (`.cc-node-a`, `aria-current`, an `aria-label` with kind and counts) and the map action (`placeMapHref`). Disclosure lists, not an ARIA tree: no tree roles without a tree's keyboard model. Folding lives in `state.placesOpen` (this visit only, like the Chronicle's folded days); `_routeChanged` and the first load call `_revealPlace`, so opening a place in the section unfolds its ancestors (never the place); `_afterRoute` keeps the open row in view beside the pane. The guides are CSS (`.cc-tree-sub>.cc-node::before/::after`, the stem under an open caret); `is-path`/`is-pathline`/`is-pathnode` brighten the way to the open place. A place's page: `nav.cc-crumbs` (recorded ancestors only, the place last with `aria-current="location"`), the kind's icon, a map preview (`.cc-minimap.is-place` at its `focusEventId`; not beside the full map), *Dentro* chips with icons.
- Language: `setLang(code)` swaps `this.t` and `this.model` (one cached model per language via `_modelFor`), updates `<html lang>`/title and re-renders in place — route, filters, scroll and map view are kept. The language is never in the URL.
- Party filter: one `filters.pcs` shared by the Chronicle chips (selection: none = all) and the map's party rows (visibility via `toggleVisibleCharacter`; all lit = `[]`, all off = `[NO_ONE]`). Matching is OR over `characterIds`; events without PCs show only with no filter or when `NO_CHARACTER` is selected.
- Overlays — the help centre (`state.help` = `{view:"help"|"glossary"}`) and the universal search (`state.search` = `{open,q,active,more}`) are dialogs (`data-dialog`), never routes. Each owns one same-URL history entry (`_pushOverlay`), so Back/Android's gesture closes it (`_overlayPopped`); ✕/Esc consume it (`_popOverlay(then)`, `then` runs after the pop); following a link from inside replaces it with the destination (`_goFromOverlay`, no dead Back press). Any route change closes them. Focus: kept on open (`_keepFocus`), trapped (`_trapFocus`), restored on close; opening an entry from an overlay focuses its heading. `Ctrl/⌘+K` toggles the search; `/` still focuses the Chronicle filter.
- Help & tours — `_buildHelp` (three tours with a Done mark, “What's in each section?” from `nav.desc.*`, six FAQ `<details>`; the glossary tab built from `EVENT_TYPES`/`QUEST_STATUS` + map marks). ### Data

`componentDidMount()` fetches `characters`, `routes`, `events`, `sessions`, `quests` (required), `npcs`, `locations`, `lore` (optional; 404 = none) and `data/i18n/es-AR.json` (optional content translation, always loaded so search is bilingual), then `this.model = this._modelFor(lang)`. Data-quality issues are logged to the console as warnings. The full schema is documented in `docs/data-model.md`; in short:

- `events.json` — the core entity. `{id, session, title, summary}` required; optional `campaignDay`, `igDate`, `igLabel`, `order`, `type`, narrative depth for important moments only (`description` = what happened, `consequences[]` = what changed, `unresolved[]` = what is still open — shown only on the event page, never invented; none of the real events has them yet), `locationId`, `xp`/`yp` (both or neither — events without coordinates have no pin), `characterIds[]` (PCs only), `npcIds[]`, `questIds[]`, `relatedEventIds[]`. `date` is a legacy sort key, **not** the real play date.
- `sessions.json` — keyed by session number; `title`, `playedOn` (real date), `dateLabel`, `ig{start,end,rest}`, `effects[]`, `activePlots[]`/`completedPlots[]` (each plot may carry `questId`), optional `recap: { summary?, highlights?: [eventId of that session, 3–5] }` for "Previously on…" (without it the recap lists every recorded event, unranked; no session has one yet).
- `quests.json` — `{id, title, status, giver, giverId?, summary, objectives?[], sessions[], characterIds[]}`.
- `characters.json` (PCs) / `npcs.json` (`category`: person|deity|creature|faction, `aliases[]`, `race`, `factionIds[]`, `relations[{id,label,reverseLabel}]`) — ids must be unique across both files.
- `locations.json` — `{id, name, aliases[], kind, parentId}` + optional own map position `xp`/`yp`/`mapPrecision` (`exact`|`approximate`; both or neither; never on a plane; a reference only — it never moves an event; set in the map editor, never inferred). Without it the map focus comes from the place's first event with `xp`/`yp`; planes never get one. The tree uses recorded `parentId`s only — never regroup places by inference (e.g. from lore facts); unknown parents and loops are validator errors, a missing/unknown `kind` a warning (shown as a plain place).
- `routes.json` — `{ pcId: [{xp, yp, leg?, break?, session?, locationId?}] }`. The **only** source of dashed lines (never derived from events). Order kept (revisits stay); `break: true` = unrecorded gap, no line; same `leg` id on ≥2 visible characters = one shared line. Never edit coordinates for presentation.
- `lore.json` — Lore of Exandria (Critical Role canon), a layer *beside* the campaign: `{ sources: {id:{label,url?,community?,spoilers?}}, entries: { <personOrPlaceId>: { references:[{source,url,title}], summary?, facts?:{<LORE_FACTS key>:text}, basedOn?, lastReviewed? } } }`. Never alters campaign fields, relations or search (a test compares builds with/without it). Summaries/facts without a valid https reference are rejected. Rendered as a collapsed `<details key=…>` at the end of the page (folds again per entity), links `target=_blank rel="noopener noreferrer"`. Curated, original, spoiler-free text only — no fetching/scraping Fandom at runtime, no images; DM-original NPCs get no lore. Spanish under `lore` (and `loreSources`) in `data/i18n/es-AR.json`.
- `data/i18n/es-AR.json` — Spanish content keyed by id (`events`, `sessions` by number with positional `activePlots`/`completedPlots`/`npcs`/`notes`/`effects`, `quests`, `people`, `places`). English `data/*.json` stays the source of truth; never translate ids, dates, coordinates or `questId`s. Session-log name matching always uses the English `name` (`nameEn`).

Links are stored once and reversed in the model. Session-log `npcs[].name` entries attach to a person/place only on an exact (case-insensitive) match with a `name` or `alias` — never fuzzy matching.

> **Quests vs. session plots — intentional two-view split (do not "de-duplicate").** `quests.json` is the current campaign-level rollup (one row per quest, with `status`). The `activePlots`/`completedPlots` inside `sessions.json` are the *per-session snapshots* of those threads (evolving text). They deliberately overlap in narrative; plots point at their quest with `questId`, and quests list their sessions in `sessions[]`. Maintaining a quest means updating **both**: the session's plot (history) and the quest entry (current state).

### Adding a new session or event

The Taller del Cronista (`#/taller`) does steps 1–7 through forms and exports a package; incorporate it with `node tools/apply-draft.js <package.zip>` (then `npm test`). By hand:

1. Add the session to `data/sessions.json` (keyed by number, with `title` and `playedOn`).
2. Append events to `data/events.json` (`session`, `campaignDay`, `igLabel`, `type`, links). Add any new NPCs/places to `npcs.json`/`locations.json` first.
3. Route waypoints go in `data/routes.json[characterId]` as `{xp, yp}` percentages, if the party moved — shared `leg` id when they travelled together, `"break": true` after an unrecorded jump. Don't invent journeys that weren't played.
4. Update `data/quests.json` (status, summary, `sessions[]`) and give the session's plots their `questId`.
5. If a new NPC/place is a verified canon entity, optionally add its reference + spoiler-free summary to `data/lore.json` (checklist in `docs/data-model.md`).
6. Optionally: `description`/`consequences`/`unresolved` on the session's important events, and a `recap` (highlights/summary) on the session — only with what the user provides; never fill them in from inference.
7. Add the Spanish text to `data/i18n/es-AR.json` (events `title`/`summary`/`igLabel` and any narrative fields; the session log and `recap.summary`; changed quests). Missing entries fall back to English.
8. A new file loaded at start (new `data/*.json`, script, portrait) must also go in `PRECACHE` in `sw.js`, with a `VERSION` bump.
9. Run `npm test` (or at least `node tools/validate-data.js`). All `data/*.json` files must stay valid JSON — no comments, no trailing commas, all keys quoted.
